# 01 — 專案總覽與環境建置

## 一、專案本質

這個專案叫 `mvweb1002`（Maven Web 1002），是一個 **純 JSP / JSTL 的練習專案**。

它不像一般企業系統那樣有 Servlet、Service、DAO 分層，而是把所有東西都塞在 `.jsp` 檔裡。
這是刻意的設計 —— 目的是讓學習者專注在 **JSTL 標籤**本身，而不是後端架構。

```
使用者瀏覽器
    │  HTTP 請求
    ▼
Tomcat (Servlet 容器)
    │  讀取 webapp 目錄
    ▼
JSP → 翻譯成 Java Servlet → 執行 → 產生 HTML → 回傳
    │
    ▼
JSTL 標籤函式庫提供 c: / fmt: / fn: 標籤
```

### 版本觀念提醒（容易搞混的地方）

「JSTL 版本」和「JSTL 的 URI」是兩件事：

| 世代 | Servlet | JSTL 版本 | taglib URI |
|------|---------|-----------|------------|
| 舊 | `javax.*` | 1.2 | `http://java.sun.com/jsp/jstl/core` |
| 新 | `jakarta.*` | 2.0 / 3.0 | `jakarta.tags.core` |

本專案 `jakarta.tags.core` **這種寫法同時適用 Tomcat 10.1（JSTL 2.0）與 Tomcat 11（JSTL 3.0）**，
所以就算 pom 宣告 3.0.0、在 Tomcat 10.1 上跑，URI 也不會出錯。

## 四、環境需求

### 必要軟體

| 軟體 | 需求版本 | 檢查指令 |
|------|---------|---------|
| JDK | 21 或以上 | `java -version` |
| Apache Tomcat | 10.1（本機為 10.1.25） | 解壓後看 `bin/version.bat` |
| Maven | 3.9+（選用） | `mvn -v` |
| Eclipse | 選用，建議加裝 WTP + m2e | 見下方說明 |
| 瀏覽器 | Chrome / Edge / Firefox 皆可 | — |

> **本機實測狀態**：`java -version` → `21.0.2`（已安裝）；
> `mvn -v` → 找不到指令（`mvn` 不在 PATH）。
> 因此建議 **直接用 Eclipse 內建 Maven**（m2e），不要依賴系統指令。

### Tomcat 與 web.xml 版本的對應

```
Tomcat 9   → Servlet 4.0 → web.xml version="4.0"  → javax.*
Tomcat 10  → Servlet 5.0 → web.xml version="5.0"  → jakarta.*
Tomcat 11  → Servlet 6.0 → web.xml version="6.0"  → jakarta.*  ★ 本專案
Tomcat 10.1 → Servlet 6.0 → 與 Tomcat 11 相同  ★ 本專案實際使用
```

本專案 `web.xml` 寫 `version="6.0"` + `jakarta.ee` namespace，
代表 **必須用 Tomcat 10.1 以上**，用 Tomcat 9 會直接啟動失敗。

## 五、執行方式

### 方式 A：Eclipse + Tomcat（本專案建議方式）

專案已經綁定好 Tomcat 10.1 runtime，所以：

1. 匯入專案到 Eclipse（Eclipse 會讀 `.project` / `.classpath`）
2. 確認 Facet 已帶入：右鍵專案 → `Properties` → `Targeted Runtimes` → 勾選 **Apache Tomcat v10.1**
3. 視窗 → `Show View` → 其他 → `Servers`
4. 在 Servers 視窗建立一個 `Tomcat v10.1` 伺服器
5. 右鍵伺服器 → `Add` → 選 `mvweb1002`
6. 右鍵 `mvweb1002` → `Run As` → `Run on Server`
7. 瀏覽器開啟 `http://localhost:8080/mvweb1002/`

> 若看不到 `Servers` 或沒有 Tomcat 選項，代表 Eclipse 缺少 **Eclipse Web Developer Tools**。

### 方式 B：手動部署 WAR 到 Tomcat

```powershell
# 1. 用 Eclipse 執行 Project → Clean，再 Project → Build Project
#    target/mvweb1002.war 會產生

# 2. 複製到 Tomcat
Copy-Item "target\mvweb1002.war" "C:\apache-tomcat-10.1.25\webapps\"

# 3. 啟動 Tomcat（Windows）
& "C:\apache-tomcat-10.1.25\bin\startup.bat"

# 4. 開瀏覽器
start http://localhost:8080/mvweb1002/
```

Tomcat 首次啟動會在 `webapps/mvweb1002/` 解開 WAR。
JSP 會在 **第一次被請求時** 才翻譯成 Java 並編譯，所以第一次開啟會稍微慢一點。

### 方式 C：Tomcat 直接指向 webapp 原始目錄（開發最快）

```powershell
# 開發時可讓 Tomcat 直接讀原始碼，改完存檔重整頁面即可生效
Copy-Item -Recurse -Force "src\main\webapp" "C:\apache-tomcat-10.1.25\webapps\mvweb1002"
& "C:\apache-tomcat-10.1.25\bin\startup.bat"
```

> 缺點：`WEB-INF/lib` 不會自動放 Maven 相依套件。
> 本專案的 JSTL 已經由 pom 指定版本打包，正式驗證請用方式 A 或 B。

### 驗證部署成功

| 網址 | 應該看到 |
|------|---------|
| `http://localhost:8080/mvweb1002/` | `Hello World!`（index.jsp） |
| `http://localhost:8080/mvweb1002/jstl1.jsp` | `名字: 張小明` |
| `http://localhost:8080/mvweb1002/jstl4.jsp` | `分數:85` / `等級：B` |

## 六、JSP 檔案標準骨架

除了 `index.jsp` 之外，其餘每一個 JSP 都使用以下標準骨架：

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
<!DOCTYPE html>
<html>
<head>
<meta charset="UTF-8">
<title>頁面標題</title>
</head>
<body>

    <!-- 頁面內容，JSTL 標籤寫在這裡 -->

</body>
</html>
```

### 第 1 行：`page` 指令（必寫）

```jsp
<%@ page language="java" contentType="text/html; charset=UTF-8"
    pageEncoding="UTF-8"%>
```

| 屬性 | 意義 | 不寫會怎樣 |
|------|------|-----------|
| `language="java"` | 宣告 scriptlet 用 Java | 預設就是 java，可省略 |
| `contentType="text/html; charset=UTF-8"` | **回應給瀏覽器**的編碼 | 瀏覽器會猜編碼，中文可能亂碼 |
| `pageEncoding="UTF-8"` | **來源檔本身**的編碼 | 編譯時用 ISO-8859-1，中文全毀 |

> **為什麼兩個編碼都要寫？**
> `pageEncoding` 決定「讀檔時怎麼解讀」，
> `contentType` 決定「輸出時怎麼宣告」，
> 兩者不一致就是最典型的中文亂碼來源。

### 第 2 行：`taglib` 指令（用 JSTL 就必寫）

```jsp
<%@ taglib prefix="c" uri="jakarta.tags.core" %>
```

| 前綴 | URI | 功能 |
|------|-----|------|
| `c` | `jakarta.tags.core` | 核心標籤：`set` / `out` / `if` / `choose` / `forEach` |
| `fmt` | `jakarta.tags.fmt` | 格式化標籤：`formatNumber` / `formatDate` / `parseNumber` |
| `fn` | `jakarta.tags.functions` | 函式：`length` / `toUpperCase` / `replace` / `escapeXml` |

> **前綴可以自己取**，例如本專案 `jstl1.jsp` 用了 `prefix="core"` 代替慣用的 `c`，
> 技術上合法，但全專案最好統一用 `c`。

## 七、已知問題與技術債

這些是程式碼裡實際存在的問題，撰寫新檔案時請避免。

| 檔案 | 問題 | 影響 | 建議 |
|------|------|------|------|
| `jstl5.jsp` 第 3 行 | `<%@page import="java.util.*" %>` **後面多了一個 `>`** | 頁面頂端會多輸出一個 `>` 字元 | 刪掉多餘的 `>` |
| `index.jsp` | 沒有 `page` 指令 | 現在只輸出 ASCII 沒事，日後加中文會亂碼 | 補上標準骨架 |
| `index.jsp` | 使用 `<%= %>` scriptlet | 官方不建議，HTML 與 Java 混雜 | 改用 `<% out.print(...) %>` 或 JSTL `<c:out>` |
| `jstl1.jsp` | prefix 用 `core` | 與其他檔案的 `c` 不一致，維護易混淆 | 統一改為 `c` |
| `jstl4.jsp` / `jstl5.jsp` / `jstlfunc.jsp` | `<title>Insert title here</title>` | Eclipse 骨架預設值未改 | 改成有意義的標題 |
| `jstldate.jsp` | `<p>` 標籤未閉合 | HTML 不合法，瀏覽器會自動修正 | 補上 `</p>` 或改用 `<br/>` |
| `web.xml` | `<display-name>web0929</display-name>` | 是舊範本殘留，與專案名不符 | 改成 `mvweb1002` |
| `pom.xml` | 宣告 `mysql-connector-j` 但沒用到 | 多餘的 jar 被打進 WAR | 移除，或等真的連資料庫再加回 |
| `pom.xml` | 宣告 JUnit 但沒有測試 | 多餘依賴 | 移除或補測試 |
| `web.xml` 歡迎頁清單 | 列出 `index.html` / `default.*` 等不存在的檔案 | 無害（容器會往後找），但冗長 | 可精簡為只留 `index.jsp` |

## 八、常見問題排除

### Q1：Tomcat 啟動失敗，報 `Unsupported major.minor` 或類別版本錯誤

JSP 會在執行期由 Tomcat 翻譯編譯，編譯器版本取自 **Tomcat 執行的 JRE**，
不是 Eclipse 的編譯版本。若 Tomcat 是用 JRE 11 啟動而程式碼用了 Java 21 語法，就會失敗。
解法：把 `JAVA_HOME` 指到 JDK 21，再啟動 Tomcat。

### Q2：頁面出現中文亂碼

依序檢查三處：

1. 檔案本身的編碼必須是 UTF-8（Eclipse 右鍵 → `Properties` → `Resource` → `Text file encoding`）
2. JSP 第 1 行有 `pageEncoding="UTF-8"`
3. 有 `contentType="text/html; charset=UTF-8"`
4. 頁面有 `<meta charset="UTF-8">`

### Q3：`The absolute uri: jakarta.tags.core cannot be resolved`

JSTL 套件沒有正確進入 `WEB-INF/lib`。
檢查 `pom.xml` 的 JSTL 兩個 dependency 是否都在，且 `<scope>` 為 `compile`（預設值，不可設成 `provided` 或 `test`）。

### Q4：`mvn` 指令找不到

本機 `mvn` 不在 PATH。改用：

- Eclipse 右鍵專案 → `Maven` → `Update Project`（使用內建 Maven）
- 或安裝 Maven 並將 `%MAVEN_HOME%\bin` 加進環境變數 `PATH`

### Q5：改了 JSP 但頁面沒變

- Tomcat 的 `work` 目錄有編譯快取 → 重新啟動 Tomcat
- 檢查是否把檔案複製到 Tomcat 卻沒重新部署
- 開發時建議在 `conf/web.xml` 開啟 `development="true"`，JSP 才會每次重譯

## 九、延伸方向

這個練習專案可以往以下方向擴充：

1. **加入 Servlet** — 把表單處理邏輯從 `jstl2.jsp` 抽到 Servlet
2. **加入 JSTL SQL 標籤** — 實際連 MySQL（`pom.xml` 已備好驅動）
3. **國際化** — 使用 `fmt` 的 `<fmt:message>` + `ResourceBundle`
4. **版面共用** — 用 `tagfile` 或 `c:import` 抽出共用的 header/footer
5. **表單驗證** — `<c:if>` / `<c:choose>` 加上 `<form:errors>` 概念
6. **加入單元測試** — 把判斷邏輯抽成 EL 運算式後再測試
